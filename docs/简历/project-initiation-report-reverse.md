# Git Agent 立项报告（倒推版）

> 产品已经先做出来，本文档是事后倒推的立项论证：如果今天要重新决定"要不要做"，依据是否依然成立。
> 推导日期：2026-09-06。版本基线：1.2.1（`ui-clear-v1-file-timeline`）。竞品价格均为 2026 年公开信息，以官网为准。

## 1. 立项背景与问题

Git 是软件行业的事实标准，但学习曲线陡峭：暂存区、HEAD、变基、冲突标记等概念对非工程角色和新手极不友好。现有图形客户端存在结构性空位：

- **免费的残血**：GitHub Desktop 功能刻意精简（无交互式变基、无完整冲突编辑器）；GitKraken 免费版限制到只剩公开仓库。
- **全功能的收费或臃肿**：Tower $69~129/年订阅；Fork $59.99 买断但无 Linux、无 AI；GitKraken Pro 连年涨价至约 $96/年。
- **安全的缺失**：除 Tower 外几乎没有客户端把"可撤销、可解释、可确认"作为核心叙事，而误操作丢工作区改动是新手最大的恐惧。
- **新变量的冲击**：2026 年 AI 编程助手开始直接代用户执行 git 命令，但黑箱式代操作在合并冲突等需要人类判断的场景并不可靠。

## 2. 目标用户与需求证据

| 用户 | 核心痛点 | 需求证据（从已交付功能倒推） |
|---|---|---|
| Git 新手 / 非工程角色 | 怕背命令、怕丢数据、看不懂术语 | 简洁版三张操作卡的引导式流程、新手说明栏、危险操作后果解释与二次确认 |
| 独立开发者 / 小团队 | 要效率也要完整能力，不愿为 GUI 付订阅费 | 九大功能域全量接入：变基、LFS、Git Flow、补丁、子模块一应俱全且免费 |
| 团队维护者 | 冲突救火与历史追责耗时 | 三栏合并工具（含 AI 建议路径）、文件时间追溯（本机时间 + Git 历次保存的统一入口，连原版都没有） |
| 隐私/合规敏感团队 | 不愿把代码发给云端 AI | 默认不发送仓库内容、敏感路径与密钥内容过滤、确定性规则先行 |

## 3. 解决方案概述

一套 Rust + egui 后端，支撑两种形态：

- **Git Agent（原版）**：完整专业工作台。
- **Git Agent Clear（简洁版）**：同一后端上的引导式界面，功能完整度 = 原版，无占位功能。

关键设计决策（已被实现验证）：

1. 双应用硬隔离（Bundle ID / 配置 / 日志 / 钥匙串 / 安装包 / 更新源），互不覆盖。
2. 一切长耗时操作遵循"立即反馈 + 异步任务 + 忙碌门控 + 完成后释放"的制度化模式。
3. AI 走"建议 + 确认"路线：确定性规则 → 逐块建议 → 用户应用 → undo 可撤销，不绕过确认、不直接写工作区。

## 4. 市场与竞品位置

详见 PRD 第 8 节（`docs/product-prd-reverse.md`）。定位结论：

- 横向空位：**免费 + 全功能 + 引导式安全操作**，在 GitHub Desktop（免费残血）与 Tower/GitKraken（全功能收费）之间。
- 纵向威胁：AI 代执行 git。应对：把 AI 定位为解释者和建议者，人保留确认权——这恰好强化"安全网"叙事而非削弱。

## 5. 范围

**做**：桌面三平台（macOS/Linux/Windows）安装包；Git 全工作流界面化；双形态；本地优先的 AI 辅助。

**不做**（已有明确边界）：

- 不做无后端的占位功能。
- 不做独立 HTTP 代理设置页（继承系统/Git 配置）。
- 简洁版在独立 Release 源建立前不做自动更新（绝不回退到原版安装包）。
- AI 不绕过用户确认、不直接覆盖工作区。

## 6. 技术方案与可行性

- **技术栈**：Rust 2024 + eframe/egui 0.31，单仓库三可执行（主程序、合并工具、差异工具）。
- **可行性证据**：667 项自动化测试通过、0 失败；Release 构建、codesign、DMG 校验全通过；双应用同机并行实测；简洁版九大功能域在隔离仓库完成实操验收。
- **质量制度**：AGENTS.md 固化了长耗时操作状态切换规范与顶栏拖拽规范，新功能必须带回归测试。

## 7. 里程碑（实际走过的路径）

1. `ui-guided-v1` ~ `v10`：十个功能域分阶段接入。
2. `ui-clear-v1-full-acceptance`：全功能、测试、安装包、人工复核通过。
3. `ui-clear-v1-history-crash-fix` / `ui-clear-v1-file-timeline`：稳定性修复与差异化能力（文件时间追溯）。
4. 当前：AI 建议合并阶段 1（确定性候选收集）完成，待提交。

## 8. 资源与成本

- 主要成本是个人/小团队的开发时间；无服务器与云服务依赖（本地优先）。
- 外部成本仅签名/分发相关；AI 能力的模型调用成本由用户自带 API Key 承担。

## 9. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| AI 代劳 Git 截流 GUI 需求 | 高 | merge-ai 路线把 AI 纳入"建议 + 确认"框架，强化而非对抗 |
| 个人项目维护带宽 | 中 | 测试门禁 + 里程碑标签，保证任意时刻可回退、可发布 |
| 竞品降价/免费化 | 中 | 护城河在安全叙事与双形态，非价格 |
| 分发渠道薄弱（无独立 Release 源） | 中 | 路线图已列"发布基建"项 |

## 10. 成功指标

沿用验收口径：实操可验证、回归有覆盖、界面有反馈；发布门禁为全量测试 + 签名 + 安装包校验 + 干净工作树。

## 11. 立项结论

痛点真实、空位存在、方案已被 667 项测试与全量实机验收证明可行、最大外部威胁（AI 代劳）已有明确的对冲路线。**倒推结论：立项成立，且已被实际产品验证。** 后续投入优先级：AI 建议合并阶段 2-5 ＞ 简洁版独立发布源 ＞ 真实凭据环境回归。
