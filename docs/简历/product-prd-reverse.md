# Git Agent 产品需求文档（PRD 倒推）

> 本文档基于现有代码、验收记录与文档反向推导，用于对齐产品认知；不代表原始立项文档。
> 推导日期：2026-09-04。版本基线：1.2.1（`ui-clear-v1-file-timeline`）。

## 1. 产品定位

Git Agent 是一个桌面 Git 客户端（Rust + egui，macOS/Linux/Windows），以"双形态"服务两类用户：

- **Git Agent（原版）**：面向专业开发者的完整 Git 工作台。
- **Git Agent Clear（简洁版）**：同一后端之上的引导式界面，让不熟悉 Git 的用户无需记忆命令即可完成全部日常与高级操作。

两个产品共存共立于同一台机器：独立 Bundle ID、可执行文件、配置、日志、钥匙串和安装包，互不覆盖。

## 2. 产品三要素

### 2.1 用户（Who）

| 画像 | 描述 | 使用形态 |
|---|---|---|
| P1 Git 新手 / 非工程角色（设计、运营、学生、转岗开发） | 会犯错、怕丢数据；需要中文引导、操作解释和确认保护 | 简洁版 |
| P2 独立开发者 / 小团队工程师 | 熟悉 Git，要效率与完整能力：图谱、变基、LFS、Flow | 原版 + 简洁版高级工具 |
| P3 协作团队中的维护者 | 处理 PR、审查历史、救火合并冲突、追溯文件来龙去脉 | 原版 + 三栏合并工具 |

### 2.2 需求（What）

1. **安全网需求**：危险操作（丢弃、删除、强推）必须解释后果并二次确认；提交可撤销/重做；合并会话可取消。
2. **零命令门槛**：日常全流程（克隆→改动→提交→推送→拉取→分支→冲突）纯界面完成，不需要退回终端或退回专业界面。
3. **完整性需求**：简洁版不允许"只能看不能用"的占位功能；高级能力（变基、LFS、Git Flow、补丁、子模块）同样可达。
4. **可解释需求**：每个操作说明"发生了什么、影响是什么"；新手说明栏按需开关。
5. **可信需求**：所有按钮连接真实 Git 后端；测试结果、远程数量、提交历史必须真实反映仓库状态。
6. **隐私需求**：AI 能力默认不发送仓库内容，首次启用须明示数据范围；API Key 存钥匙串。

### 2.3 场景（Where/When）

| 场景 | 典型流程 | 关键功能 |
|---|---|---|
| S1 个人日常迭代 | 打开项目 → 保存我的改动 → 暂存 → 写说明提交 → 推送 | 保存改动、提交选项、Push |
| S2 协作同步 | 开工前 Fetch 看待下载 → Pull → 完事后 Push；遇非快进/分叉按引导恢复 | 远程同步三卡片、异常恢复引导 |
| S3 并行工作线 | 创建分支做实验 → 切换 → 合并/变基回主线 → 删除分支 | 分支树、合并、交互式变基 |
| S4 冲突救火 | Pull/合并出冲突 → 三栏工具逐块取舍（可求助 AI）→ 应用结果 → 提交 | 三方合并工具、AI 建议 |
| S5 历史审计与回退 | 搜索提交 → 看差异 → 文件时间追溯 → Revert/Reset/拣选 | 历史图谱、文件时间线 |
| S6 临时切换 | 来急事 → Stash 收起 → 切分支处理 → Pop 恢复 | Stash 全流程 |
| S7 团队规范化 | Git Flow 发版、LFS 管大文件、补丁传递离线改动 | Flow、LFS、补丁 |

## 3. 功能架构（现状）

九大功能域，简洁版全部提供入口且连接真实后端（共 650+ 项自动化回归）：

1. **工作目录与仓库**：打开/创建/克隆、多项目标签、工作空间分组、窗口状态恢复。
2. **保存改动**：暂存/取消/批量、差异查看、忽略/停止跟踪/删除/丢弃（带恢复说明）、提交高级选项（立即推送/修订/跳钩子/GPG）、提交撤销重做、**文件时间追溯**（本机创建/修改时间 + Git 历次保存记录，原版无此统一入口）。
3. **与远程同步**：Fetch/Pull/Push 三卡片、高级参数、远程地址管理、PR 创建、认证/无上游/分叉/冲突的完整引导。
4. **历史版本**：提交图谱、搜索、排序、比较、检出/回退/反向提交/拣选/归档。
5. **工作线（分支）**：本地/远程分支树、跟踪、合并、变基、比较、重命名、删除。
6. **临时收起（Stash）**：Create/Apply/Pop/Drop + 范围选项。
7. **冲突与历史整理**：三栏合并工具（本地/远程取舍、手工编辑、undo/redo、AI 建议）、交互式变基。
8. **高级仓库能力**：标签、补丁、Git LFS、Git Flow、子模块/子树、归档、性能基准。
9. **设置与桌面工具**：主题/字体/语言、SSH 与身份、托管账号、可选 AI 配置、自定义 Git 操作、`.gitignore` 编辑器、快捷键、更新检查。

## 4. 核心用户旅程（验收级）

以 P1 在简洁版的首次使用为例：

1. 项目列表三张操作卡 → 选"克隆远程项目" → 填地址与位置 → 自动打开。
2. 修改文件 → "保存我的改动"第 1 步看到文件状态与本机时间 → 第 2 步暂存并写说明 → 第 3 步提交（可勾选立即推送）。
3. "和远程同步"卡片显示待上传数量 → 推送 → 数量归零。
4. 拉取遇到冲突 → 进入三栏合并 → 每块有解释和取舍按钮（或 AI 建议）→ 应用结果 → 自动暂存。
5. 全程新手说明栏解释术语；危险操作均有后果说明与确认。

## 5. 非功能需求

| 类别 | 要求 | 现状 |
|---|---|---|
| 性能 | 小窗口（768px）不闪退；大仓库历史/差异异步加载不阻塞 UI；长耗时操作统一"立即反馈 + 异步任务 + 忙碌门控 + 完成后释放" | 已制度化（AGENTS.md） |
| 可靠性 | 全量 `cargo test` 通过；每个功能入口有回归覆盖 | 667 项通过，0 失败 |
| 安全 | API Key 走系统钥匙串；危险操作二次确认；AI 默认不传仓库内容；敏感文件（`.env`、私钥）排除在 AI 候选外 | 已实现 |
| 隔离 | 原版/简洁版配置、日志、钥匙串、安装包完全隔离；自动更新源独立，绝不互相覆盖 | 已验收 |
| 可用性 | 中英文双语；浅色/深色主题；新手说明持久化 | 已实现 |

## 6. 边界（明确不做）

- 不提供无后端的演示/占位功能入口。
- 原版不做独立 HTTP 代理设置页（继承系统/Git 配置）。
- 简洁版在独立 Release 源建立前不提供自动更新，且不下载原版安装包。
- AI 合并不绕过用户确认、不直接覆盖工作区。

## 7. 验收指标（沿用现有口径）

- `✅ 实操`：真实点击并核对仓库/持久化状态变化。
- `✅ 回归`：真实调用路径有自动化测试。
- `✅ 界面`：实际打开页面核对入口、禁用态与反馈。
- 发布门禁：全量测试通过 + Release 构建 + codesign + dmg 校验 + 工作树干净。

## 8. 竞品分析（2026 年公开信息，价格以官网为准）

### 8.1 横向：同品类直接竞品

| 竞品 | 价格模式 | 平台 | 核心优势 | 核心短板 |
|---|---|---|---|---|
| GitHub Desktop | 免费（MIT） | Mac/Win | 零门槛、GitHub 生态无缝 | 功能刻意精简，无交互式变基与完整冲突编辑器，非 GitHub 托管体验弱 |
| Sourcetree | 免费 | Mac/Win | 全功能免费、LFS/Flow 齐备 | 更新缓慢、大仓库卡顿、交互式变基难用 |
| GitKraken | 免费版限公开仓库；Pro ~$4.95/月起 | 三平台 | 提交图谱最强、托管集成广 | Electron 内存占用高；免费版阉割严重（无私有仓库、无合并编辑器） |
| Fork | $59.99 买断 | Mac/Win | 原生性能快、变基/冲突体验好 | 无 Linux、无 AI、PR 集成弱 |
| Tower | $69~129/年 | Mac/Win | 无限 Undo、拖拽变基、最精致 | 贵、订阅疲劳 |
| Sublime Merge | $99（3 年） | 三平台 | 大仓库性能与 Diff 可读性顶尖 | UI 极简、无 AI、无 PR 集成 |
| SmartGit | 非商用免费；$59/年 | 三平台 | 企业合规 + Linux | UI 老旧、无 Undo |
| GitButler | 免费开源 | 三平台 | 虚拟分支创新、多模型 AI | 范式学习成本高、稳定性待验证 |

横向结论：品类价格带两极分化——"免费但残血"或"全功能但收费/臃肿"。**"免费 + 全功能 + 引导式安全操作"是空位**：简洁版对标 GitHub Desktop 的易用性但功能完整；高级能力覆盖 Fork/Tower 的专业场景但不收费。

### 8.2 纵向：替代链条

| 层级 | 替代方案 | 截流方式 | 本产品应对 |
|---|---|---|---|
| 底层 | Git 命令行 | 极客不用 GUI | 不争夺；自定义 Git 操作保留 CLI 退路 |
| IDE 层 | VS Code + GitLens、JetBrains Git | 日常 80% 操作在 IDE 内完成 | 以独立工作台补位历史整理、交互式变基、冲突三栏、多仓库管理 |
| 终端层 | lazygit / gitui / Magit | 键盘党高效替代 | 不同人群，不直接竞争 |
| 平台层 | GitHub/GitLab/Gitee 网页端 + gh CLI | PR 审查与轻量编辑上网页 | 提供"打开远程网页/创建 PR"衔接而非对抗 |
| AI 层 | Cursor / Copilot / Claude Code 代执行 git | 2026 年最大变量：AI 替用户跑命令 | AI 代操作是黑箱；本产品走"AI 建议 + 人确认"（merge-ai 计划），把 AI 变成解释者而非替代者 |

纵向结论：最大的纵向威胁是"AI 直接代劳 Git"。merge-ai 计划（确定性规则优先、逐块建议、确认后应用、可撤销）正是回应——当 AI 会写代码，人更需要能看懂、能确认、能反悔的 Git 界面。

### 8.3 差异化护城河

1. **双形态一套后端**：新手引导与专业功能不做取舍，简洁版功能完整度 = 原版，品类内独有。
2. **安全叙事**：undo/redo、危险操作后果说明、忙碌门控、双应用隔离——Tower 靠 Undo 收 $69/年，本产品免费提供同等安全网。
3. **隐私优先的 AI**：默认不传仓库内容、敏感路径过滤、确定性规则先行，适合合规敏感团队。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| AI 建议错误导致错误合并 | 确定性规则优先；每条建议附理由/置信度；应用走 undo 栈；写入前校验冲突标记与编码 |
| 用户把简洁版当"阉割版" | 功能对照表持续维护，验收记录可查 |
| 双版本混淆/互相覆盖 | Bundle ID 与更新源硬隔离，更新失败时明示而非回退 |
| 敏感内容泄漏给模型 | 候选收集阶段即过滤 `.env`/私钥/密钥内容；默认不发送仓库内容 |
